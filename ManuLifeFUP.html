III.AI primitives04

An agent is a system, not a prompt.

Model

The reasoning engine. Match capability, speed, cost, and modality to the task.

Context

The bounded working set: instructions, conversation, code, retrieved data, and tool results.

Instructions

Role, operating rules, constraints, quality bar, and definition of done.

Tools

Typed capabilities to read, search, edit, test, browse, or call external systems.

State

Progress, plans, checkpoints, task status, and durable artifacts across steps.

Evaluation

Tests, linting, policy checks, human review, and observable acceptance criteria.

IV.Agentic workflow05

The reliable loop: orient → act → verify.

Agentic systems repeatedly choose the next best action from evidence. They do not replace engineering controls; they automate work inside them.

1 · Understand

Restate the outcome, constraints, risks, and success criteria.

2 · Plan

Decompose into bounded steps and identify dependencies.

3 · Retrieve

Load only the code, docs, and data needed for the next decision.

4 · Act

Call a tool, edit a file, run a command, or delegate a subtask.

5 · Observe

Interpret actual output; never assume the action succeeded.

6 · Verify

Test against the contract, summarize evidence, and escalate uncertainty.

V.Workflow design06

Choose the right autonomy pattern.

Prompt chain

Deterministic stages with explicit artifacts. Best for repeatable, auditable processes.

Router + specialists

A coordinator selects the right agent or skill. Best when task types vary but roles are stable.

Parallel fan-out / fan-in

Independent workers explore distinct scopes, then a parent synthesizes. Best for broad analysis.

Human approval gates

Pause before destructive, privileged, costly, or externally visible actions. Best for production systems.

Design rule: automate reversible work first; require explicit approval where blast radius or ambiguity is high.

VI.Custom agents07

A reusable role + tool boundary.

In VS Code, a custom agent is a .agent.md profile that defines a specialized persona, instructions, available tools, optional model preferences, and handoffs to the next role.

Consistency

Encode the same review criteria, process, and output shape every time.

Least privilege

A planner can be read-only; an implementer can edit; a release agent can require approvals.

Portability

Workspace agents live in .github/agents/; user agents can be reused across workspaces.

VII.Custom agent anatomy08

Build a specialist in five decisions.

# .github/agents/api-reviewer.agent.md
---
name: api-reviewer
description: Review API changes for contracts and risk
tools: [read, search, usages, problems]
handoffs:
  - label: Fix approved findings
    agent: implementation
    send: false
---

Review changed API surfaces only.
Rank findings by impact and confidence.
Do not edit files. Cite file and symbol evidence.

1 · Single job

Name one outcome and make the activation description specific.

2 · Minimum tools

Expose only capabilities required for the role; fewer tools improve safety and selection quality.

3 · Evidence contract

Specify sources, output schema, confidence, validation, and stop conditions.

4 · Model fit + 5 · Handoff

Choose the model for task complexity, then define the controlled transition to the next agent.

VIII.Guided orchestration09

Handoffs keep humans in control.

VS Code handoffs create suggested next-step buttons between custom agents. They preserve relevant context while giving the developer a review point before the next phase begins.

Clarify

Resolve ambiguity and freeze acceptance criteria.

Plan

Read-only analysis, design, risks, and test strategy.

Implement

Make scoped changes and run targeted checks.

Review

Independent correctness, security, and maintainability pass.

Release

Human approves deployment, merge, or external action.

Set send: false when the next phase should wait for explicit user confirmation.

IX.Reusable skills10

Package procedure as an on-demand capability.

Agent Skills are an open-standard folder format containing instructions, scripts, examples, templates, and references. Copilot loads relevant skill content when the task matches the skill description.

Portable

Works across compatible agents, including VS Code, Copilot CLI, and Copilot cloud agent.

Composable

Multiple focused skills can combine into a larger workflow without one giant instruction file.

Context efficient

Detailed procedural content stays out of the prompt until the skill becomes relevant.

X.Skill anatomy11

Create a skill that agents can discover correctly.

# .github/skills/api-contract-review/SKILL.md
---
name: api-contract-review
description: Review REST API changes for
  backward compatibility, versioning, and error contracts.
  Use for OpenAPI or controller changes.
---

# Workflow
1. Read the changed contract and implementation.
2. Compare request, response, and status semantics.
3. Run the contract test command in [tests](./tests.md).
4. Return breaking changes and remediation.

Metadata is routing logic

The required lowercase-hyphenated name must match the directory. The description must say what the skill does and when to use it.

Keep SKILL.md navigable

Put the default workflow up front. Link optional references, examples, scripts, and templates with relative paths.

Test activation and outcome

Try positive and negative trigger prompts, then verify the skill produces the promised artifact and validation evidence.

XII.Sub-agents13

Delegate bounded work into isolated context.

A sub-agent receives a focused task, works in an independent context, and returns a summary to the parent. The parent spends tokens on the useful result—not every exploratory read and tool call.

Isolation

Research, noisy logs, or broad exploration do not pollute the main implementation context.

Parallelism

Independent scopes can run concurrently, reducing elapsed time rather than individual token use.

Specialization

Run custom agents as sub-agents to apply security, performance, testing, or accessibility perspectives.

XIII.Parallel execution pattern14

Fan out only when work is truly independent.

Sub-agent A

Contract impact

Inspect API schema and consumer compatibility. Return breaking changes only.

Sub-agent B

Security impact

Inspect changed trust boundaries. Return exploitable findings with evidence.

Sub-agent C

Test impact

Map acceptance criteria to missing or affected tests. Return a minimal test plan.

Parent synthesis: deduplicate → resolve conflicts → rank by impact and confidence → decide the next action.

Good split

Different files, questions, data sources, or review lenses with no write overlap.

Bad split

Sequential dependencies, shared mutable files, duplicate exploration, or tiny tasks where coordination costs more.

XIV.Delegation contract15

Make every delegation self-contained.

Objective

One concrete question or deliverable. Avoid “analyze everything.”

Scope

Relevant files, boundaries, assumptions, exclusions, and permissions.

Evidence

Required citations, commands, test output, or source quality.

Return contract

Exact output shape, priority order, confidence, and maximum length.

Review only the payment retry path. Read-only. Find correctness defects caused by the new backoff logic.
Return at most five findings as: severity | file:symbol | evidence | recommended fix | confidence.
Ignore style. If no high-confidence defect exists, say so explicitly.
XV.Token optimization16

Tokens are the agent’s working memory budget.

Every request competes for a finite context window. Useful evidence must share space with system instructions, customizations, conversation history, tool schemas, retrieved files, tool output, and the model’s response.

Too little context

More guesses, repeated searches, incorrect assumptions, and brittle edits.

Too much context

Higher latency and cost, diluted attention, contradictory evidence, and earlier compaction.

Right-sized context

Only authoritative, current, decision-relevant evidence for the next action.

XVI.Optimization playbook17

Reduce waste without starving the decision.

1 · Start with a contract

State outcome, scope, constraints, non-goals, and done criteria once.

2 · Attach precisely

Prefer relevant files and symbols over whole repositories or giant folders.

3 · Search, then read

Use indexing and semantic search to locate evidence before loading full files.

4 · Limit tools

Disable irrelevant MCP servers and tools; their definitions also consume context.

5 · Isolate noise

Move broad research and verbose diagnostics to sub-agents; return compact summaries.

6 · Reset intentionally

Start a fresh session after a phase change; carry forward a verified handoff summary.

Before you press send.

Key takeaways

Build systems that are bounded, reusable, and observable.

Agents operationalize roles

Define a focused job, least-privilege tools, evidence standards, and controlled handoffs.

Skills operationalize know-how

Package portable procedures and resources so expertise loads only when relevant.

Sub-agents protect context

Delegate independent, noisy work and bring back concise, decision-ready summaries.

Token optimization is information design

Give the model the smallest authoritative context that fully supports the next decision.
